# MVP 資料模型與權限設計

版本：0.1  
資料庫：Drizzle ORM + SQLite（兼容本地 SQLite 及 Cloudflare D1）

## 1. 設計原則

- 結構化資料放在 SQLite；PPT、PDF、圖片、學生上傳及備份檔的位元組放在受保護的檔案／物件儲存，`file_assets` 只保存擁有者、類型、大小及 `storage_key`。
- 主鍵由伺服器產生 UUID／ULID。資料庫預設時間使用 SQLite 的 UTC `YYYY-MM-DD HH:MM:SS` 格式；應用程式寫入時間時必須在同一部署中維持一致格式。每日 AI 限額的 `usage_date` 按學校設定時區（預設 `Asia/Macau`）產生 `YYYY-MM-DD`。
- `created_at` 有資料庫預設值；每次修改資料時，應用程式必須明確更新 `updated_at`。
- 所有授權均在伺服器查詢中執行。資料表關聯可防止孤兒資料，但不能代替角色及課程範圍檢查。
- 帳戶、課程及教務資料優先改為 `archived`，不直接刪除。學生離班後，前台不再顯示歷史資料；實際刪除按校方保留政策另行執行。

## 2. 實體分組

### 帳戶、班別與課程

| 資料表 | 用途 |
| --- | --- |
| `users` | 管理員、教師、學生共用帳戶；角色只容許 `admin`、`teacher`、`student`。保存密碼雜湊、首次改密碼及鎖定狀態。 |
| `auth_sessions` | 只保存工作階段 token 的雜湊、期限及撤銷時間，不保存明文 token。 |
| `classes`、`class_memberships` | 班別及師生名單。`member_role` 必須與 `users.role` 一致，由服務層在寫入時驗證。 |
| `courses` | 課程及唯一加入代碼；一位教師為 MVP 課程擁有者。 |
| `course_class_assignments` | 把整個班別分配到課程。 |
| `course_enrollments` | 課程的實際學生名單，記錄由班別、加入代碼或手動加入。班別分配時批量建立此表，方便固定權限及保留加入來源。 |
| `units` | 課程單元、排序及發布狀態。 |

### 教材、題目與作業

| 資料表 | 用途 |
| --- | --- |
| `file_assets` | 上傳檔案的受控中繼資料。下載前仍須檢查其所屬教材或答案權限。 |
| `materials` | 單元教材，可連結原始檔、網頁內容或影片；中英文內容分開保存。`ai_review_status` 阻止未確認 AI 內容發布。 |
| `rubrics`、`rubric_criteria` | 教師自訂評分準則、權重、滿分及排序。 |
| `questions` | 七種題型、雙語題幹、選項、答案、起始程式、參考解及指定概念。題目複製到課程後才加入作業；`answer_key_json`、`solution_code` 永遠只由教師／評分服務讀取。 |
| `test_cases` | 程式題公開及隱藏測試。學生 API 不可直接查詢此表；只能經過安全投影取得公開案例。 |
| `assignments`、`assignment_items` | 練習／功課／測驗／考試及其候選題目，包含時間、次數、補交、隨機、答案公布和 AI 開關。 |

隨機抽題時，服務層先從 `assignment_items` 選題，再在建立草稿提交的同一交易內建立排序後的 `submission_answers`。這些答案列同時是該次作答的固定題目快照，重新整理頁面不會抽到另一組題目。

### 作答、執行與評分

| 資料表 | 用途 |
| --- | --- |
| `submissions` | 每次作答；`(assignment_id, student_id, attempt_number)` 唯一。 |
| `submission_answers` | 該次作答的固定題目、文字／JSON／檔案答案、分題分數及教師覆核。 |
| `code_snapshots` | 自動儲存、執行、提交及貼上事件的程式版本；序號在每個答案內唯一。 |
| `code_runs` | 隔離執行工作的排隊、資源用量、輸出及錯誤。 |
| `test_results` | 每次評分執行的案例結果。對隱藏案例，學生回應只可包括通過／失敗，不可包括實際輸入、預期輸出或詳細錯誤。 |
| `grades` | 每次提交的一筆總成績，分開保存自動分、AI 建議分、教師調整分及正式分。只有 `released` 成績可出現在學生端。 |
| `learning_sessions` | 以心跳累積有效學習秒數；不把背景分頁或長時間閒置計入學習時間。 |

### AI、通知與營運

| 資料表 | 用途 |
| --- | --- |
| `ai_provider_configs` | 供應商、模型及加密後 API 金鑰。`api_key_hint` 只供遮罩顯示。 |
| `ai_settings` | 唯一 `global` 設定，控制供應商、提示層級、全校／學生每日限額、對話保存和保留日數。 |
| `ai_conversations`、`ai_messages` | 任課教師可查看的學生 AI 對話。停用保存時不建立這兩表的內容。 |
| `ai_daily_quotas`、`ai_usage` | 前者以 `(user_id, usage_date)` 原子預留／結算每日請求與 token 額度，後者保存每次 AI 請求的模型、用途、token、延遲和結果；即使停用對話保存仍寫入用量，但不寫提示／回應正文。 |
| `announcements` | 班別或課程公告及發布時段。 |
| `notifications`、`email_deliveries` | 每位收件人的站內通知、已讀狀態和可選電郵傳送結果。 |
| `feature_flags` | 可逐項開關的功能，例如排行榜、遊戲化、電郵、考試模式及排程備份。 |
| `system_settings` | 上傳上限、Python 套件白名單、執行限制、時區及備份保留期等 JSON 設定。敏感值必須先加密才可保存。 |
| `audit_logs` | 登入、拒絕存取、內容、成績、設定及備份操作。`metadata_json` 不可包含密碼、API 金鑰或完整學生答案。 |
| `backup_records` | 手動／排程備份的狀態、儲存位置、校驗碼及還原驗證時間；不保存備份內容本身。 |

建議首批功能鍵為 `gamification`、`leaderboard`、`email_notifications`、`exam_mode`、`scheduled_backups`；建議系統設定鍵為 `school.timezone`、`uploads.max_bytes`、`python.allowed_packages`、`python.time_limit_ms`、`python.memory_limit_mb`、`python.output_limit_bytes` 及 `backups.retention_days`。

## 3. 伺服器端權限矩陣

| 資源 | 管理員 | 教師 | 學生 |
| --- | --- | --- | --- |
| 帳戶與班別 | 全校管理 | 所教班別學生只讀；可按政策重設密碼 | 只可讀／改自己的非敏感資料及密碼 |
| 課程、單元、教材 | 全校管理 | 只可修改 `owner_teacher_id = current_user.id` 的課程；校內共用資源只讀 | 只可讀有效選課下已發布且已到發布時間的內容 |
| 題目及 rubric | 全校管理 | 自己建立的可修改；`sharing_scope = school` 的已發布題目只讀／複製 | 只能透過已發布作業取得安全題目投影 |
| 提交、程式、執行、成績 | 按管理權限查看 | 只可查看自己課程中已選課學生的資料 | 必須同時符合 `student_id = current_user.id`；成績須已發布 |
| AI 對話及用量 | 設定與全校統計 | 只可查看自己課程學生的對話／用量 | 只可查看自己的對話及剩餘限額 |
| 通知 | 全校管理 | 可向自己班別／課程發布 | 只可讀及標記自己的通知 |
| 功能、系統、稽核、備份 | 管理員專用 | 無權限 | 無權限 |

每個教師範圍查詢都必須由 `courses.owner_teacher_id` 或教師的有效 `class_memberships` 起步，再連到學生；不可只因請求包含一個 `course_id`、`student_id` 或 `submission_id` 就信任它。

學生題目投影必須排除：

- `questions.answer_key_json`、`questions.solution_code`；
- 未到 `assignments.answer_release_at` 的完整解釋及標準答案；
- `test_cases.visibility = hidden` 的輸入、預期輸出、限制及權重；
- 隱藏案例對應 `test_results.actual_output`、`error_message`；
- 未經教師確認的 AI 評語、AI 建議分及教師草稿。

## 4. 主要查詢與索引

索引只針對 MVP 實際流程建立：

- 登入：唯一 `username`／`token_hash`；工作階段以 `(user_id, revoked_at, expires_at)` 查詢，另以 `expires_at` 清理過期資料。
- 班別及選課：班別名單以 `(class_id, member_role, status)`；個人班別／課程以 `(user_id, status)` 或 `(student_id, status)`。
- 課程內容：教師課程以 `(owner_teacher_id, status)`；單元／教材以 `(course_id 或 unit_id, position)` 及發布狀態查詢。
- 待辦功課：以 `(course_id, status, publish_at)` 及 `(course_id, due_at)` 配合學生選課查詢。
- 批改中心：以 `(assignment_id, status)` 找提交；以 `submission_id` 找固定題目和答案。
- 程式歷程及執行佇列：以 `(submission_answer_id, created_at)` 查歷程，以 `(status, created_at)` 取待執行工作。
- AI 限額：全校按 `usage_date` 彙總，學生按 `(user_id, usage_date)` 彙總；教師對話按 `(course_id, last_message_at)`。
- 通知：一般清單用 `(recipient_id, created_at)`；未讀清單使用只包含 `read_at IS NULL` 的部分索引。
- 稽核與備份：分別按操作者、實體、動作、狀態和建立時間查詢。

遷移完成後執行 `PRAGMA optimize`。正式接入查詢後，應以代表性資料執行 `EXPLAIN QUERY PLAN`，確認上述路徑使用預期索引；不要因單一低頻後台查詢再增加索引。

## 5. 必須以交易／批次完成的操作

1. 班別加入課程：建立 `course_class_assignments`，並批量 upsert `course_enrollments`。
2. 開始隨機作業：檢查時段和次數，建立 `submissions`，再建立固定排序的 `submission_answers`。
3. 提交程式題：建立最後 `code_snapshots`、評分 `code_runs` 並更新提交狀態。
4. 發布成績：更新分題覆核、`grades`、提交狀態、通知及稽核紀錄。
5. 變更 AI 或系統設定：更新設定及寫入不含秘密內容的 `audit_logs`。

在 D1 中，每個 prepared statement 只包含一個 SQL statement；同一操作的多個 statement 使用 `batch()`。AI 請求須先以帶限額條件的原子 upsert 更新 `ai_daily_quotas`，供應商回應後再結算預留額並寫入 `ai_usage`。任何寫入失敗都不可留下「有提交但沒有固定題目」或「成績已發布但沒有稽核」的半完成狀態。

## 6. 安全與資料生命週期

- 密碼使用 Argon2id 或等級相當的強雜湊；重設後設定 `must_change_password = true`。登入名稱及電郵在寫入前統一正規化大小寫。
- API 金鑰由伺服器金鑰加密後才寫入 `encrypted_api_key`，一般查詢永不 select 此欄。
- AI 對話清理工作依 `conversation_retention_days` 刪除訊息／對話；`ai_usage` 可保留不含正文的統計紀錄。
- 檔案下載以關聯資源重新授權，不提供可猜測的永久公開路徑。
- 備份開關使用 `feature_flags.scheduled_backups`；每次備份都寫入 `backup_records`，完成後以校驗碼及定期還原演練驗證。
- 資料庫連線啟用 foreign keys；部署遷移後執行 foreign key check、integrity check 和 `PRAGMA optimize`。
- D1 會強制外鍵；任何日後新增的本地 SQLite 連線都必須在每次連線建立時執行 `PRAGMA foreign_keys = ON`，不能只在遷移時設定一次。
