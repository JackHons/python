# 本地部署與 Phase 8 驗證界線

## Docker Compose（macOS M1 目標）

`docker-compose.yml` 的核心流程由以下服務組成：

- `gateway`：唯一對外入口（3000）；只在 gateway→backend 私有 hop 注入 `BACKEND_INTERNAL_TOKEN`。
- `web`：網站 UI，無 host port，由 gateway 轉發非 API 路由，依賴 backend healthy。
- `backend`：Node HTTP service，持有 SQLite、storage、exports、backups volumes，並以 server-only token 呼叫 runner；不直接對外 publish。
- `runner`：Python 執行服務，只在 `runner-internal` network，沒有 host port。
- `converter`：PPT/PPTX 轉換 worker，使用 LibreOffice／Poppler，沒有 host port或外部網絡，讀取同一受控 DB/storage volume。
- `email-worker`：非同步處理 email outbox；正式 SMTP 未配置時 fail closed，不影響站內學習流程。`mailpit` 只在明確啟用 `smtp-test` profile 時作本地 SMTP sandbox。

不強制 `linux/amd64`；本機 macOS ARM64 已用 Colima 實際建置及啟動四個 `linux/arm64` image。先準備設定：

```bash
node scripts/create-local-env.mjs
docker compose config
docker compose build --pull
docker compose up -d
docker compose ps
sh scripts/smoke-test-compose.sh
```

必要 secrets：`BACKEND_INTERNAL_TOKEN` 和 `RUNNER_SERVICE_TOKEN` 至少 24 字元；`AI_MASTER_KEY` 用於 server-side authenticated encryption。瀏覽器不會接收這些值。`BACKUP_ENABLED` 預設關閉。

`scripts/create-local-env.mjs` 會為本地純 HTTP 測試寫入 `SESSION_COOKIE_SECURE=false`；因此照上方命令建立新 `.env` 後即可在 HTTP 保存 session。若 `.env` 已存在、未使用 helper，或入口是 HTTPS，請明確設定 `SESSION_COOKIE_SECURE=true`（Compose 預設值）；PowerShell：`$env:SESSION_COOKIE_SECURE="true"; docker compose up -d`；bash：`SESSION_COOKIE_SECURE=true docker compose up -d`。production 或任何 HTTPS 入口不得使用 `false`。

停止服務：

```bash
docker compose down
```

此命令不刪除 volumes。`docker compose down -v` 是破壞性操作，應在保存並驗證 backup 後才使用。

輔助腳本：`scripts/backend-init.sh`（啟動 backend）、`scripts/seed-demo.mjs`（只限非 production；必須指定 `SEED_CREDENTIALS_FILE`，以 0600 一次性寫出初始憑證並強制首次改密碼）、`scripts/provision-local-admin.mjs`、`scripts/smoke-test-compose.sh`、`scripts/backup-host.sh`、`scripts/restore-isolated.sh`（拒絕覆蓋 live DB）、`scripts/redacted-logs.sh`。不要把 credential file 提交到 repo。

本地 Docker 管理員 provision/rotate（不會把密碼印到 stdout）：

```bash
LOCAL_ADMIN_CONFIRM=PROVISION_LOCAL_ADMIN \
  node scripts/provision-local-admin.mjs
# 已存在 admin-local 時使用：
LOCAL_ADMIN_CONFIRM=PROVISION_LOCAL_ADMIN \
  node scripts/provision-local-admin.mjs --rotate
```

命令會把隨機初始密碼寫到 `.local-secrets/admin.json`（目錄 0700、檔案 0600、首次登入必須改密碼），並停用 Phase 8 的 `admin-demo`、`container-teacher`、`container-operator` 及 `container-student-*` fixture 帳戶、撤銷其 sessions。它只封存帳戶，不刪除課程、提交或 Docker volumes；`.local-secrets/` 已加入 git 與 Docker ignore。若檔案已存在，provision 會拒絕覆寫，必須明確使用 `--rotate`。

本機學生試用帳戶（demo-only，不適用正式課堂）：

```bash
LOCAL_STUDENT_DEMO_CONFIRM=PROVISION_STUDENT_DEMO \
  node scripts/provision-student-demo.mjs
```

這個可重複執行的命令會新增／輪替 `student-demo`，設定 `must_change_password=false`，並建立或重用已發布的示範 Python 課程、單元、教材及公開／隱藏測試案例功課。隨機密碼只寫入 `.local-secrets/student-demo.json`（0600），不會印到 stdout；它不會刪除 live 資料或 volumes。

## Host-only fallback

若測試機沒有容器工具，可用 bundled Node 22、Python 3 跑 domain/API 及主機 Runner：

```bash
npm ci
npm run build
npm run test:all
npm run load:phase8
python3 scripts/phase8-runner-host-smoke.py
```

本次 Docker gate 已在 macOS ARM64 Colima 實跑；容器 build 內的 Node 22 `npm ci` 亦通過。若主機沒有 npm，請使用 repo 配置的 bundled pnpm/node；這不等同 host-side clean npm install。Docker 40 人樣本與證據見 `docs/任務包/證據/phase8b-compose-load.json`。

`phase8-host-load.json` 使用 40 個脫敏 fixture、注入 fake runner，記錄登入、課程讀取、grade/submit、教師分析及 hidden canary。主機 Runner 腳本另驗證 40 concurrent、429 queue、network/subprocess/pip AST policy、timeout、output limit。兩者都不能取代 Docker network/cgroup/ARM64 證據。

## 教材庫操作與限制

- 教師在「教材庫上傳」加入檔案；後端先 quarantine，再做副檔名/MIME/signature 檢查後 release。PPTX 必須是完整 ZIP/OOXML，不能只以 `PK` header 冒充。
- 可用格式為 PPT/PPTX、PDF、DOC/DOCX、PNG/JPEG、ZIP；單檔 decoded bytes 上限 25 MiB。HTTP transport 以 base64 JSON 傳送，所以 gateway/backend request body 必須容納其編碼膨脹，但 storage limit 仍固定 25 MiB。
- ready asset 預設 `private`；owner/admin 可改 `school`。教師只可選自己 ready asset 或 school asset；學生不可列出教材庫。
- 課程教材草稿需選明確 course/unit/asset，可設定中英文內容、position、`allowDownload`。學生下載 route 會再次驗證 active enrollment、published、ready 及 `allowDownload`。
- PPT conversion 由獨立 converter 消費 durable job。`queued`／`running` 只代表等待／處理中；只有 `succeeded` 及有效 page manifest 才顯示網頁投影片。worker 使用 job 專屬臨時目錄、逾時、頁數與輸出大小限制，完成或失敗後清理；原檔不會改寫。
- 學生投影片與 PDF route 會再次驗證有效選課、課程／單元／教材發布狀態；網址及 DTO 不包含 storage path。轉換失敗會保留脫敏錯誤供教師判斷，不能假稱預覽完成。

教材庫真實 fixture 與安全回歸證據：`docs/任務包/證據/material-library-validation.txt`；真實 PPTX 轉換與預覽證據：`docs/任務包/證據/phase9b-validation.txt`。

## Runner 安全說明

Compose runner 使用 read-only root、tmpfs、no-new-privileges、cap drop、PID/memory/CPU limits 及 internal network；但長駐容器不是每作業即棄的強安全邊界。未完成 gVisor/Kata/microVM 前，不應用於公開服務或高風險考試。

目前 Compose 明確使用 `RUNNER_ISOLATION_MODE=local_process` 與
`RUNNER_REQUIRE_STRONG_ISOLATION=0`。這是本機／內部相容模式，能力端點會標示
`local_process`／`weak`；它保留每作業臨時目錄、process-tree timeout、輸出／資源限制、
AST capability policy 與 secrets 正向白名單，但不提供 kernel、egress 或跨容器的強隔離。

若設定 `RUNNER_REQUIRE_STRONG_ISOLATION=true`，或選擇尚未配置的
`RUNNER_ISOLATION_MODE=strong_external`，Runner readiness 與 execution 會 fail closed，
不會靜默退回 local process。HTTP execution request 不能選擇隔離模式。

這個 Slice A 只完成服務端隔離契約與弱模式 containment regression；整體 P0 仍未完成。
正式公開／高風險考試必須另外提供並在實際目標主機驗證 gVisor、Kata、microVM 或等效
每作業 disposable runtime、egress deny、resource enforcement、完整回收與惡意程式測試。
