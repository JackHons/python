# Python 學習平台任務包

版本：0.1（Phase 0 基線）  
適用環境：Apple Silicon macOS（M1）＋Docker Compose；首輪驗收 40 人同時在線。  
工作方式：主 agent 負責調度、整合、驗收及風險決策；各 phase 由 `luna_worker` 或其指定 worker 執行，完成後必須提交測試結果及可重現證據。

## 1. 目前基線

現有 repo 是「可操作前端原型＋Python Runner 技術基礎」，不是可供學生正式使用的完整後端。已存在：

- React／TypeScript 原型頁面，包含學生、教師、管理員視圖及練習工作台示意。
- SQLite／Drizzle schema 及初始 migration 草稿，已列出多數產品實體。
- Web `/api/run` 代理、獨立 Python Runner、Docker Compose、Runner 單元測試及少量 HTML 測試。
- 需求、網站架構、資料模型及本地部署文件。

尚未完成或尚未證明：伺服器端登入及 RBAC、所有教務／教材／題目／提交 API、資料持久化流程、完整安全評分、AI 供應商、通知、報表、備份、前後端整合、40 人負載及安全驗收。現有 Runner 只屬 MVP 隔離層，不能直接宣稱能安全執行任意不可信程式。

## 2. Phase 總覽與依賴

```text
P0 基線與契約
  └─> P1 資料層、帳戶、RBAC、班別、課程
        └─> P2 教材、檔案、題庫、功課、提交快照
              └─> P3 Runner、執行、測試、批改
                    ├─> P4 AI 供應商、限額、對話、教師審核
                    ├─> P5 即時課堂、通知、電郵
                    └─> P6 分析、匯出、稽核、備份
                          └─> P7 前後端整合及端到端流程
                                └─> P8 Docker、負載、安全、內部試用放行
                                      └─> P9A 實際功能審計、缺口矩陣與內部試教核心閉環
                                            └─> P9B 學生學習流程、教師分析、AI 與 PPT 預覽
                                                  └─> P11 角色路由、教材版本、AI 提示與即時課堂
```

Phase 4、5、6 可在 P3 的核心提交／成績契約穩定後並行，但 P7 必須等這三者的 API 契約確定。P8 是最終閘門，不得用原型畫面或單元測試代替。

## 3. 交付規則

每個 phase 的 worker 必須：

1. 先閱讀本索引、相依 phase 計劃及現有需求／資料模型。
2. 只修改計劃指定的範圍；若需要跨界修改，先在交付報告列明理由、影響及回退方法。
3. 以 migration、API 契約、測試及可重現命令交付，不以手動操作或截圖作唯一證據。
4. 完成前執行該 phase 的測試；若環境阻塞，必須保存完整命令、錯誤輸出、已排除項目及替代證據。
5. 給主 agent 一份變更摘要、測試摘要、證據路徑、剩餘風險及未完成項目。

## 4. Phase 目標速覽

| Phase | 目標 | 主要 P1 風險 |
| --- | --- | --- |
| P0 | 建立基線、契約、範圍及驗收方式 | 找出隱性耦合及不可證明項 |
| P1 | 可持久化的帳戶、RBAC、班別、課程 | 啟用 SQLite foreign keys；確定 course／class／enrollment 關係 |
| P2 | 教材、PPT／檔案、題庫、作業、提交草稿 | submission ↔ question 固定關係與權限邊界 |

| P4 | 可配置 AI、原子配額、對話保存及教師確認 | AI quota 原子性、秘密及未審核內容不發布 |
| P5 | 即時課堂、站內公告、電郵通知 | 角色範圍、重送冪等及隱私 |
| P6 | 分析、Excel／PDF、稽核、備份及還原 | 報表權限、資料完整性、備份可恢復 |

| P9 | 審計需求與真實產品落差，修復內部試教 P0/P1 閉環 | CSRF、發布範圍、功課政策、套件政策、教務與批改不得只靠 UI |
| P9B | 真實學生課程路徑、分層 AI、教師分析與 PPT 轉換預覽 | AI key／quota、analytics scope、preview 權限及轉換隔離 |
| P11 | Canonical 角色路由、教材可靠性、多 AI provider、逐層提示與即時課堂 | known-ID scope、相容 method、學生安全 projection、課堂 lock／ended guard |

## 5. 版本閘門

- P1 閘門：登入、換密碼、角色範圍、班別及課程 CRUD 在真實 SQLite 中通過整合測試。
- P2 閘門：教師建立內容，學生只能看到已發布版本；每次 submission 的題目集合不可因刷新或重試而改變。
- P3 閘門：公開案例可詳列，隱藏案例只回傳通過／失敗；每個 run 可追溯到唯一 snapshot 及 submission answer。
- P4 閘門：配額在併發請求下不超額；AI 產物在教師確認前不能進入學生端或正式成績。
- P5 閘門：課堂、公告及通知只落到授權收件人，重試不重複發送。
- P6 閘門：教師只能導出其班別／課程；備份可驗證並完成一次還原演練。
- P7 閘門：瀏覽器主要流程與 API 狀態一致，無「畫面顯示成功但未寫入」的假成功。
- P8 閘門：M1 Docker 可重建及重啟保留資料，40 人測試及安全測試有可重現報告。
- P9A 閘門：Gateway CSRF、學生已發布投影、功課時間／重交／公布政策、Runner 套件白名單及帳戶／班別／批改核心在 server enforcement 與真實 UI 同時通過；後續缺口保留明確狀態。
- P9B 閘門：學生能以真實 API 走課程→單元→教材／練習；分層提示次數由 server 持久化；教師分析 scope-first；AI 無配置 fail closed；PPT 真實轉換且 preview 經 enrollment／發布權限；未做項仍明確標 Partial／Missing。
- P11 閘門：canonical role deep links 與 API RBAC 同時通過；教材版本不隱式更新已發布課程；AI provider 只能顯式單一啟用且提示逐層審核；即時課堂可重連並由 server 以 423 鎖定寫入。
