Scope
------
The Runner HTTP broker talks only to a narrow authenticated Unix-socket
protocol. A host-owned trusted launcher owns the Docker/runsc policy and starts
one disposable job container per accepted request. The normal Compose profile
remains local_process/weak; strong mode is an explicit override.

Implemented boundary
--------------------
- services/runner/job_worker.py: one-shot bounded JSON stdin/stdout worker.
- services/runner/execution_policy.py: bounded job/source policy and a 384 MiB
  child address-space ceiling below the launcher's 512 MiB container ceiling.
- services/runner/Dockerfile.job: Python 3.12 job image, fixed non-root UID,
  numpy/pandas/matplotlib dependencies, no broker or service token.
- scripts/runner-strong-launcher.py: fixed Docker argv, runsc, --network=none,
  read-only root, cap drop, no-new-privileges, memory/CPU/PID/tmpfs limits,
  non-root identity, --pull=never, stdin input, scoped cleanup, and an actual
  startup self-probe using the same runsc job path before readiness is attested.
  Student timeout is kept inside the worker; launcher infrastructure gets a
  separate bounded startup/cleanup grace budget.
- services/runner/server.py: bounded Unix-socket client, strict capability
  handshake, strong timeout budget large enough for the launcher budget,
  sanitized fail-closed infrastructure errors, and no local fallback in strong
  mode. A worker result with timed_out=true remains an HTTP 200 job result.
- docker-compose.strong-runner.yml: explicit strong-mode deployment override
  mounting only the launcher socket directory, never Docker/containerd sockets.
- scripts/runner-strong-runtime-smoke.py: black-box HTTP readiness, target-host
  canary creation/verification, numpy,
  pandas, matplotlib Agg, student timeout, permitted-code egress canary,
  filesystem/repository/data and secret-environment canaries, cross-job state,
  runtime error, memory/PID pressure, recovery, and bounded 40-job checks.
