Scope
-----
The initial inspection was read-only. A user-owned WSL2 target was then
provisioned and configured; no project source was changed.

Host and WSL
------------
- Windows 11 Home, x64.
- WSL version 2.6.3.0; default WSL version 2.
- `wsl -l -v` shows only the `docker-desktop` distro, running as WSL2.
- There is no user-owned Ubuntu/Debian or other Linux distro with its own
  Docker Engine/containerd.
- Inside `docker-desktop`, the environment identifies as Docker Desktop's
  managed distro; Docker CLI access to a distro-owned daemon is refused.
- `runsc --version` in that managed environment returns permission denied. This
  is not treated as evidence that gVisor is installed or usable.

Linux-owned WSL2 target
-----------------------
- User-owned distro: `Ubuntu-StrongRuntime`, WSL2.
- Ubuntu 24.04.5 LTS, kernel `6.6.87.2-microsoft-standard-WSL2`, x86_64.
- Independent Docker Engine 29.8.1 with containerd 2.3.5 and runc 1.5.1.
- Systemd is running in this distro and owns the local Docker service/socket.
- Docker Desktop's managed daemon was not used for these probes.

Docker Desktop managed daemon
-----------------------------
- Docker Desktop 4.84.0 / Engine 29.6.2, linux/amd64.
- The Windows Docker CLI reaches the `desktop-linux` managed daemon.
- Registered runtimes include `runc`, `io.containerd.runc.v2`, and an NVIDIA
  runtime; `runsc` is absent.
- The daemon's default runtime is `runc`.
- A local `--runtime=runsc` probe already failed with
  `unknown or invalid runtime name: runsc`.

gVisor registration and real probes
-----------------------------------
- Installed official `runsc` package version `release-20260921.0`.
- Registered with the independent Docker daemon using `runsc install`; Docker
  reports runtime `runsc` at `/usr/bin/runsc` alongside runc.
- Real local image `local/runsc-busybox:probe` executed successfully through
  `docker run --rm --runtime=runsc`.
- `--network=none`: outbound probe was blocked.
- `--read-only`: rootfs write was blocked; explicit tmpfs remained writable.
- `--user 65532:65532`: non-root execution returned UID 65532.
- `--cap-drop=ALL` and `--security-opt=no-new-privileges` were accepted.
- `--memory=32m`, `--cpus=0.25`, and `--pids-limit=32` were accepted; the
  memory over-limit workload was terminated/rejected.
- A PID over-fork workload under `--pids-limit=8` was rejected with resource
  exhaustion.
- A forced `docker kill` on a runsc container with `--rm` left no container
  behind.
- Pulling `hello-world` from Docker Hub timed out because the standalone WSL
  daemon has no proxy configuration; the real probes therefore used a local,
  no-pull image. This does not affect runtime registration evidence.

Conservative result
-------------------
The supported Linux-owned runtime target now passes the bounded B0 gate. The
Docker Desktop managed VM remains out of scope and was not modified. Do not
implement the production StrongExternalExecutor until the application-side
broker/launcher integration, adversarial suite, and 40-job disposable-sandbox
test are completed.
